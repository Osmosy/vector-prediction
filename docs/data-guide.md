# Гайд по данным: что собирать и в каком виде

Человекоязычная версия для специалистов по продажам, маркетологов и директоров.
Техническая (для агента/аналитика): см. README и `references` в skill timesfm-forecasting.

## Период и шаг

| Параметр | Минимум | Нормально | Идеально |
|---|---|---|---|
| Период истории | 4 месяца | 1 год | 2 года |
| Шаг | день | день | день |
| Точек (строк) | 120 | 365 | 730 |

- Шаг — день (мясо/ритейл/кампании меняются ежедневно).
- Минимум 4 месяца: модель учится на повторяющихся паттернах (день недели, сезон).
- Год — чтобы покрыть сезон (май, Пасха, НГ). Без прошлогоднего сезона прогноз на сезон слепой.
- Пропуски (не работал магазин / не вели данные) — не страшно, модель интерполирует. Но если пустышек > 1/3 периода — период хуже.

## Данные по уровням

**Уровень 1 — обязательно:**
- продажи за каждый день (штуки или кг), один продукт = один столбец.

**Уровень 2 — сильно повышает точность:**
- календарь акций (1 = была акция) — прошлое И план на будущее;
- праздники (0 обычный / 1 предпраздничный / 2 праздник) — известно всегда;
- цены за день — прошлое + план по прайсу;
- посещаемость/трафик — только прошлое.

**Уровень 3 — бонусы:**
- прогноз погоды на будущие дни (мясо-гриль зависит от погоды);
- маркетинговые активности (реклама, дегустации);
- производственные ограничения (для сверки прогноза с планом).

Правило: будущее указывается только для того, что ЗНАЕТЕ ЗАРАНЕЕ.
Не выдумывать будущие числа — это портит прогноз.

```
2025-09-01,142.5,89.0,530,0,0,329.90
2025-09-02,138.2,91.3,511,0,0,329.90
2025-09-06,189.7,95.1,604,1,0,319.90
```

## Файл плана (plan.csv) — на прогнозный период

```
date,promo,holiday,price_sosiski
2026-09-05,1,0,319.90
2026-09-06,1,0,319.90
```

Продаж в плане НЕТ — их и узнаём.

## Что получите (пример)

```
date,forecast,cautious,optimistic,promo
2026-09-05,196.8,184.2,209.5,1
2026-09-06,204.1,191.0,217.3,1
```

- forecast — основная цифра (план закупки/производства);
- cautious (10-й перцентиль) — «худший реалистичный день», ориентир для скоропорта;
- optimistic (90-й перцентиль) — запас для заморозки/долгого хранения.

## Частые ошибки оформления

1. Числа с запятой («142,5») — надо с точкой (142.5), без слова «кг» в ячейке.
2. Строки «итого»/«среднее» в конце — удалить, модель примет их за дни.
3. Даты в разных форматах в одном файле — выбрать один (лучше 2026-09-05).
4. Смешение единиц (шт и кг в одном столбце) — нельзя.
5. Отрицательные числа — вычистить.
6. Пустые дни без торгов — ставить 0, не удалять строку.

## Чек-лист перед загрузкой

- [ ] История ≥ 4 месяцев, лучше год+, шаг день
- [ ] Один продукт = один столбец, единицы одинаковые
- [ ] Даты без пропущенных дней (или пропуски объяснимы)
- [ ] Календарь акций: прошлое + план на будущее
- [ ] Праздники отмечены
- [ ] Планируемые изменения цен указаны
- [ ] Будущие числа не выдуманы
- [ ] Числа с точкой, без «итого»
