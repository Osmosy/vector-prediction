# Лицензионное соответствие: разделение контуров

Дата: 2026-09-04. Основа: полный текст TimesFM Non-Commercial License v1.0
(https://huggingface.co/google/timesfm-3.0-pytorch/raw/main/LICENSE).

## Двухконтурная схема

| | Контур A (ПРОД) | Контур B (RESEARCH) |
|---|---|---|
| Модель | TimesFM 2.5-200M | TimesFM 3.0-330M |
| Лицензия весов | Apache-2.0 | TimesFM Non-Commercial v1.0 |
| Роль | Все боевые прогнозы: планы производства, закупки, KPI кампаний, клиентские отчёты | Бенчмарк и сравнение подходов |
| Код | `scripts/campaign_forecast.py` | `scripts/research_bench.py` |
| Результаты идут в | Производственные решения | Внутренний отчёт о сравнении моделей |

## Что говорит лицензия 3.0 (точные формулировки)

- **Non-Commercial Purpose** = «use for testing, evaluation, or research not tied
  to commercial gain, production deployment, or revenue generation... provided
  the results are not used in commercial decision-making, client deliverables,
  or paid products/services».
- **Outputs не являются Derivative**: «Outputs are not considered Derivatives
  under this License» — сами числа прогноза лицензия не квалифицирует как
  производную модель.
- **Запрещено**: использование «for any commercial or production purposes»;
  дистрибуция модели/деривативов; дистрибуция Outputs для commercial/production
  целей; обучение, файнтюн или **дистилляция** 3.0 в модели «for commercial use».

## Правила соответствия (обязательны)

1. Прогноз 3.0 **не попадает** в производственные планы, закупки, клиентские
   артефакты и любое commercial decision-making. Никогда.
2. Прогноз 3.0 используется только для внутреннего сравнения с контуром A
   (точность/скорость/поведение ковариатов) — это testing/evaluation.
3. Скрипты двух контуров физически разделены: `campaign_forecast.py` импортирует
   только 2.5 API; `research_bench.py` — отдельный вход, не встраивается в прод.
4. Гибрид «3.0 черновик → 2.5 финал» допускается, только если 3.0-прогон
   остаётся внутренним исследованием и финальные цифры выдаёт 2.5.
5. Не дистрибутировать веса 3.0 и не переупаковывать их в этом репо
   (скачивание — на стороне пользователя с HF, по его собственной лицензии).

## Примеры: разрешено / запрещено

| Сценарий | Статус |
|---|---|
| Прогноз продаж для плана производства (2.5) | ✅ контур A |
| Сравнить MAE 2.5 vs 3.0 на нашей истории (3.0) | ✅ контур B |
| Взять цифру 3.0 в план закупки, «потому что точнее» | ❌ нарушение |
| Регулярный прод-пайплайн на 3.0 | ❌ нарушение |
| Дистилляция 3.0 в маленькую коммерческую модель | ❌ прямо запрещено |
| Продать прогноз 3.0 как услугу/деливерабл | ❌ нарушение |
| Продать прогноз 2.5 как услугу | ✅ Apache-2.0 |
| 3.0 через BigQuery AI.FORECAST | ✅ (условия Google Cloud, не эта лицензия) |
| Переписать свой код, но грузить веса 3.0 | ❌ это Derivative |

## Путь к коммерческому 3.0

1. Мониторить HuggingFace `google/timesfm-3.0-pytorch` — Google исторически
   переводил проверенные версии в Apache-2.0 (2.5 так и стал).
2. BigQuery AI.FORECAST: интеграция 3.0 анонсирована «coming weeks»
   (блог Google Research, 31.08.2026) — доступ через API = условия Google Cloud.
3. Коммерческая лицензия напрямую: «you must obtain a commercial license from
   Company» — предусмотрена лицензией, по запросу.
